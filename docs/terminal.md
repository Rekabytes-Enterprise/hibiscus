# Terminal UI

Start `hibiscus` in a terminal for an interactive chat. Hibiscus starts Pi with installed extensions disabled, one explicit approval gate, and only the selected built-in `read`, `bash`, `edit`, `write` and bundled `goal`/`loop_status` tools active, so Pi-installed MCP extensions do not start (also during auth handoffs). Running Pi directly still uses your normal configuration. `hibiscus --continue` resumes the latest Pi session for this directory; `hibiscus --sessions` opens the startup numbered picker. Inside the full-screen chat, `/sessions` and `/models` use docked pickers above the composer. Full-screen `/sessions` and `/continue` show a loading notice while session files are scanned on a worker; press Esc to cancel the scan or its picker. Keys typed during a scan are buffered for the composer after loading, not sent to Pi. Enter during loading is ignored rather than replayed as an accidental prompt. The existing numbered line-mode and startup `--sessions` paths remain synchronous. A cold scan still takes filesystem time, but need not block the full-screen view. `/models` lists Pi's configured models as `provider/model`, sorted by provider and model ID; selecting one switches providers and models in the current chat without a new login if Pi already has access. Pi remains responsible for credentials and reports any model-access errors.

**`/thinking`** queries Pi for levels supported by the active model and opens a keyboard/wheel picker with the current level marked. `/thinking high` selects a reported level directly; invalid or unavailable levels are not sent to Pi. The level applies to subsequent Pi requests and follows Pi's session behavior; Hibiscus does not display raw thinking text or persist a second model setting. Select a model with `/models` first if none is active.

**`/compact [instructions]`** asks Pi to summarize older active-branch context; optional text focuses its summary (e.g. `/compact Preserve the deployment decisions`). Compaction uses the selected provider/model and can consume time or tokens. It keeps original Pi session entries, may report “nothing to compact” or fail on provider errors, and never becomes a chat prompt. Hibiscus shows a working phase and waits for Pi's correlated `compact` response—not an assumed `agent_settled` or the ordinary 30-second metadata deadline. During full-screen compaction, typed text/images remain in the composer; Enter/queue shortcuts do not submit until compaction finishes. Esc asks Pi to abort, waits for both correlated compact and abort responses, and disconnects if cancellation is uncertain. Pi owns automatic compaction independently; this command triggers it manually.

A successful **`/new`** opens a blank full-screen chat: it clears the visible transcript, input/attachments, scroll position, and failed-prompt recovery buffer. The model stays selected and the header updates from Pi. Saved sessions are not deleted; use `/sessions` to return to them. If Pi rejects or cancels creation, the current conversation stays visible. Line mode retains its plain “Started new session” confirmation.

## Input and navigation

| Action | Key |
|---|---|
| Send while idle / steer while Pi runs | Enter |
| Queue a follow-up while Pi runs | Ctrl+Q on WSL; Alt+Enter elsewhere |
| Insert a newline | Ctrl+Enter (Ctrl+J fallback); multiline terminal paste stays in the draft |
| Search for a file path in the draft | Type `@`, then use Up/Down and Enter or Tab to insert a match |
| Attach an image from the clipboard | Alt+V on WSL; Ctrl+V elsewhere |
| Remove staged images | Ctrl+X |
| Move within a draft | Left/Right, Up/Down, Home/End; Ctrl+B/F and Ctrl+A/E also work |
| Delete at the cursor | Backspace or Delete (Ctrl+D when the draft is nonempty) |
| Scroll a long draft | Mouse wheel over the input rows; cursor movement follows the visible region |
| Delete a character | Backspace |
| Stop a running Pi response and clear its queue | Esc |
| Exit from an empty composer | Ctrl+D (or `/quit`) |
| Scroll transcript | Mouse wheel, PageUp/PageDown |
| Copy visible transcript text | Drag and release (automatic copy), or press Ctrl+C while text is selected |
| Quit from empty/full draft | Ctrl+C twice within two seconds, Ctrl+D with an empty draft, or `/quit` |
| Navigate a model/session picker | Up/Down, wheel, PageUp/PageDown |
| Accept a picker choice | Enter |
| Cancel a picker | Esc |

Full-screen dialogs share the `/models` panel style: raspberry rounded borders, the same outer margin, highlighted choices, a scrollbar when needed, and Enter/Esc hints. This includes model/session pickers, login/logout choices, Pi handoff confirmation, Pi `select`/`confirm`/`input`/`editor` requests, and masked Codex authorization input. Confirmations default to Cancel; approval menus default to Deny. Dialogs temporarily take keyboard focus and preserve any unsent composer draft. Text dialogs use end-of-input editing; secret input is masked. Long descriptions/commands wrap literally in a scrollable detail area (PgUp/PgDn). Explicit dialog timeouts and Esc cancel without approval.

Type `/` to see only Hibiscus's supported commands; a prefix such as `/m` filters the suggestions. Up/Down or the wheel changes the highlighted suggestion. **Tab** completes without running it, **Enter** runs it, and **Esc** dismisses the list without erasing the text. Type `/help` to see chat commands, including `/loop <goal>`.

In full-screen chat, type `@` at a word boundary to find a local file or directory. Matching names appear in a picker; Up/Down chooses one and **Enter or Tab inserts its path at the cursor without sending the prompt**. Directories remain open for more completion; filenames containing spaces use `@"quoted path"`. Fuzzy search uses `fd` when available (respecting its ignore rules), with a limited current-directory/path-prefix fallback otherwise; searching runs off the UI thread. This behaves like Pi's interactive path mention, **not** Pi's CLI `@file` upload: Hibiscus sends the selected `@path` as ordinary Pi RPC prompt text, never the file contents or an image attachment. Pi may use its `read` tool to inspect a referenced file. The picker is unavailable in line/piped mode; if you need to attach an image, use the separate image-paste shortcut.

The full-screen composer grows with explicit newlines and wrapped text to **five visible rows**, then scrolls internally. Arrow keys move the insertion cursor through the draft (Up/Down move between visual rows); Home/End move to the start/end of the current logical line. Backspace and Delete edit at that cursor. The wheel over the input rows can still scroll the draft independently; editing brings the cursor back into view. Slash-suggestion navigation takes priority over Up/Down until suggestions are dismissed. The composer cursor stays visible at its insertion point during editing **and** Pi runs. Hibiscus requests a steady (non-blinking) block cursor in its alternate screen and restores the terminal's default cursor style on exit or Pi handoff. Terminals that ignore the steady-cursor request may still blink according to their own settings; no global terminal preference is changed. The status flower animates while Pi runs; elapsed time updates once per second. Ctrl+Enter requires a terminal that sends a newline or distinct modified Enter sequence (Kitty/CSI-u or modifyOtherKeys); use Ctrl+J if your terminal sends it as ordinary Enter. Shift+Enter sequences are also accepted where the terminal distinguishes them, but some terminals send Shift+Enter as ordinary Enter. Full-screen menus are unavailable in line mode, where numbered selection remains available. For clipboard images, press **Alt+V on WSL** or **Ctrl+V elsewhere**, matching Pi's platform defaults. Hibiscus accepts both shortcuts, including CSI-u/modifyOtherKeys encodings. The border shows the attachment count (not an inline image preview). Add optional text and press Enter to send, or Ctrl+X to remove all staged images. Image-only prompts work too. With a selection, Ctrl+C requests a copy without quitting. Otherwise its first press clears the draft/attachments and shows a two-second **Ctrl+C again to quit** hint; a second press within two seconds exits. Any other key disarms the shortcut. Ctrl+C during an active response does not exit; use Esc to stop Pi. Ctrl+D still exits when the composer is empty. Remove attachments before running slash commands.

Clipboard image paste supports macOS via AppKit/`osascript`, WSL via Windows `powershell.exe`, Wayland via `wl-paste` (`wl-clipboard`), and X11 via `xclip`. It reads the clipboard on the machine running Hibiscus, not an SSH client's clipboard. Windows Terminal can intercept Ctrl+V for terminal paste, which is why WSL uses Alt+V instead. The chosen shortcut must reach Hibiscus. Normal terminal text paste is separate from image paste. In full-screen mode Hibiscus requests **bracketed paste** (`CSI ?2004h`) and disables it on exit/handoff; terminal-sent `CSI 200~ … CSI 201~` content is inserted as one draft, with CRLF/CR normalized to newline and tabs expanded, never submitted by its embedded Enter bytes. The paste is bounded to 8 KiB; oversized or invalid UTF-8 paste is rejected without submitting a partial prompt. If your terminal/multiplexer does not support bracketed paste, unmarked newlines are indistinguishable from pressing Enter; configure paste forwarding in that terminal before relying on this behavior. Physical terminal verification is still needed. Up to four PNG/JPEG/GIF/WebP images, at most 10 MiB each, can be staged; macOS and WSL screenshots are converted to PNG in memory. Clipboard reads are asynchronous and bounded; failures leave the text draft intact. Images are sent as Pi RPC `images` content blocks, without temporary image files or base64 in the visible transcript. Pi owns persisted session content and provider handling; use an image-capable model.

## Unattended `/loop [--strict] <goal>` (experimental)

In an interactive full-screen chat, `/loop <goal>` asks Pi to set a checklist, work toward the goal and perform real Playwright browser E2E/UAT. Pi is instructed to install project-local browser tooling **on the user's machine or server** when needed, start the app, test controls and flows, inspect logs and captured screenshots, repair failures, and repeat after each settled run. While `/loop` is active, Hibiscus bypasses its own dangerous-`bash` approval prompt; this is an explicit unattended mode and does not bypass OS permissions, provider limits or Pi tools. Esc cancels the active run and exits the loop; normal approvals then resume. Between settled Pi turns the footer remains in a `Loop · review/continue` state instead of briefly showing the idle `Enter send` hint. An unworkable prerequisite may be reported as blocked.

**Default `/loop <goal>` is guided mode.** Built-in skill-style instructions let Pi choose test tools, test names and artifact formats. There is no separate reviewer call or mandatory report schema. Pi signals completion through `loop_status`; Hibiscus displays **“Pi reports the requested work and tests complete. Not independently verified.”** The footer shows loop activity and optional model-reported checklist, without a misleading verified-UAT counter. Missing SDK reviewer support does not block guided mode.

**Opt-in `/loop --strict <goal>`:** completion is gated on the **first named** Pi `goal` checklist remaining unchanged and complete, an internal `loop_status` candidate-complete tool result (not a visible magic string), a validated Playwright JSON report with nonzero passed tests named for every step and nonempty screenshot/browser-console attachments, and a later Pi image read of a reported screenshot. Pi's reply stays ordinary prose; while Hibiscus checks it, the raspberry footer shows loop activity and separate `Checklist done/total · UAT verified/total` counts, rather than an idle hint or a misleading model-reported 100% success. If space is narrow, UAT takes priority over optional metrics. Only after all checks pass does Hibiscus show `✓ Loop finished`. The reviewer returns all missing criteria together; each next turn names those specific gaps instead of repeating the whole work request. If Pi repeatedly asserts completion without new tools or changed UAT evidence, Hibiscus folds repeated visible summaries (Pi's persisted transcript remains intact), requests a targeted recovery, then reports a stalled blocker instead of looping forever. Reviewer/provider failures remain separately classified. After each settled turn, a separate reporting-only model call through Pi's selected SDK reviews the immutable original request against the proposed checklist, UAT evidence and recent report. Missing scope can be added before the checklist is locked; an unavailable reviewer blocks completion with a safe, specific reason (SDK capability/load, model availability, provider failure, cancellation, truncated response, invalid verdict-tool arguments, or timeout). The reviewer returns native `submit_verdict` tool-call arguments, not JSON chat text. A missing/malformed tool call gets one bounded correction using the same evidence; this does not rerun app tests. The report-only tool executes no actions. Strict schemas are preferred where Pi/provider support them, with ordinary tool calling otherwise; no custom Pi installation is required. A model verdict of “met” without the required UAT evidence is treated as **not met**, with the missing checks sent back to Pi. **This is still not proof of perfect behavior:** matching test titles, attachments and a model verdict cannot guarantee meaningful assertions or that every feature was exercised. The verifier is a separate provider call and may not appear in Pi's session usage snapshot. No real-browser/provider acceptance was run here. Rate-limit classification is advisory and Pi's own retries may already consume attempts; see [the precise limits and synthetic test scope](loop-design.md). Review the test cases, logs and screenshots before relying on a completion claim.

### Highlighting browser-test failures

Before the first browser run, guided mode instructs Pi to configure project-local Playwright with `screenshot: 'only-on-failure'` and `trace: 'retain-on-failure'`; strict mode uses `screenshot: 'on'` so passing tests also yield screenshots. Both request `video: 'retain-on-failure'` only where supported, without overwriting other app settings. This makes Playwright capture a page-level failure automatically before teardown; it is still model-guided setup, not an automatic Hibiscus configuration change. Both modes instruct Pi to identify the failed control by name/locator and expected versus actual behavior, preserve the unmodified failure screenshot, then create a **separate annotated PNG** with a raspberry/red outline or arrow. Annotations are labelled as test annotations, never alterations presented as original evidence. A browser that fails before opening a page cannot produce a control screenshot; missing controls or unavailable capture must be explained rather than fabricated. Pi is instructed to retain traces, produce a Markdown failure summary with artifact paths, and capture the same flow after repair. These are model instructions, not a built-in screenshot annotator or a guarantee of visual analysis. No deliberate bug is requested unless the user's task asks for one.

### Submitting browser-test evidence (strict mode only)

Pi can submit a saved report with `loop_status` action `submit_evidence`, `projectDir`, `reportPath`, and optional `supportFiles` for test sources, server logs and earlier failure reports. The tool immediately receives actual accepted counts and exact missing checks through an internal client bridge; no human dialog is opened. This handles tests invoked via `cd app && …`, redirected JSON, or stdout truncated by Pi. The report is a regular JSON file inside the project, at most 4 MiB; relative artifact paths resolve against the project or report directory. Both inline base64 and file-backed screenshot/console attachments are supported, including duplicate attachment names. After submission, Pi reads a reported screenshot (a decoded copy of an inline image is supported). Missing files, invalid JSON, stale reports, missing tests and attachments produce specific feedback. Accepted report counts are retained; subsequent tool work triggers a bounded source fingerprint comparison rather than erasing the report on every bash command. Changed tracked app/test/config sources mark evidence `stale` with a reason; unchanged source content preserves it across log/server checks. Report freshness uses modification timestamps with one-second filesystem tolerance, not cryptographic proof. The reviewer receives validated per-criterion evidence metadata, bounded console and test-source excerpts, supplied supporting evidence, and missing/stale reasons—not merely `evidence=false`. Screenshot pixels are not passed to the reviewer. Source monitoring and excerpt limits are described in [Loop design](loop-design.md); these checks do not guarantee all runtime dependencies or semantics are correct.

## Live steering and follow-ups

In **full-screen chat**, the composer remains editable while Pi runs. Press Enter to send a **steering** message after the current assistant turn's tool calls; press **Ctrl+Q on WSL** or **Alt+Enter elsewhere** to queue a **follow-up** for after the agent finishes. Ctrl+Enter still inserts a newline. Both queued modes support the same text/image attachments as an ordinary prompt. The composer hint shows the active shortcuts while typing. Pi's `queue_update` event supplies separate steering/follow-up counts in the working footer and a dim pending list above the composer (`Waiting · Steering: …` or `Waiting · Follow-up: …`). If an item leaves the queue before Pi emits its user-message event, it briefly reads `Sending…`. No pending item is shown as a sent user chat row.

Hibiscus sends Pi RPC `prompt` with `streamingBehavior: "steer"` or `"followUp"` and correlates the response by a unique ID. A successful response means **accepted/queued, not delivered or complete**. If a queued command's acknowledgement arrives after Pi's final settlement, it is still only an acknowledgement: Hibiscus must not reopen the run or wait for an invented event. It still waits for any reported nonempty Pi queue to drain. Only Pi's `message_start` event for a user message moves the item into the chat as an ordinary user row (the initial prompt's user event is not echoed twice). Hibiscus waits for Pi's final `agent_settled` while continuing to accept input. Pi's `steeringMode` and `followUpMode` settings govern how messages in each queue are drained. Hibiscus does not implement a second retry/scheduling engine. A rejected queue request restores the text and images if the composer is empty; if you've started a newer draft, it stays untouched and `/restore` is available after the run. Submission before Pi accepts the original prompt is held for explicit resubmission. Local commands such as `/new`, `/quit`, `/login`, or `/sessions` cannot run or be sent as prompts while Pi is busy; wait until it settles or press Esc. Esc clears Pi's queued messages before aborting; interrupted delivery may be uncertain, so check history before resending. Line mode and piped input retain their existing input behavior.

## Rendering and cursor stability

Full-screen output compares the new view with the previous painted rows and writes only rows that changed. An unchanged composer is not repainted for each reply chunk or spinner tick. Streaming text is coalesced on a roughly 33ms frame budget (the RPC poll can add a small delay); typing, cursor movement, and explicit UI transitions repaint immediately. Settlement flushes the final text rather than waiting for another animation tick.

Each update uses synchronized-output markers (`CSI ?2026h/l`) so supporting terminals present the completed frame and final cursor position together. Cursor visibility changes only when focus/viewport changes, not per streamed chunk. Resize and return from Pi handoff force a fresh view; the transcript, composer, status row and docked panels expand with terminal width with two-column margins on wider terminals and one-column margins below 60 columns. Input reflows on resize without changing the draft sent to Pi. Full-screen extension dialogs render through the same cached panel component rather than writing directly to the terminal. Cleanup releases synchronized output before returning the terminal. `NO_COLOR` still uses these non-color rendering optimizations; piped output remains plain.

If your terminal or multiplexer misbehaves with synchronized updates, set `HIBISCUS_NO_SYNC_UPDATE=1` before launching Hibiscus. Row-diff rendering and batching still work without the markers, but an unsupported terminal can expose intermediate hardware cursor movement. A real terminal visual check is needed to assess flicker; PTY tests verify emitted frames, not the terminal's presentation.

## Status and transcript

The assistant is presented as Hibiscus in this client. The bundled Pi extension adds identity and operational guidance to Pi's prompt (structured sections on supported Pi versions, or additions to Pi's existing rendered prompt on older hooks). Identity guides answers such as “Hibiscus, powered by Pi.” Operational guidance asks the model to inspect safely first, clarify materially ambiguous requests before acting, make conservative assumptions for minor reversible details, respect “don't code yet,” and report only verification actually performed. It does not rewrite generated replies, hide the real provider/model, replace Pi's base instructions, or implement a second agent. Model behavior is probabilistic: neither identity wording nor asking every needed clarification is guaranteed; review the proposed action when stakes are high. The header shows the workspace, Pi-selected provider/model, current thinking level (when a model is selected), and session. Hibiscus reads the thinking level from Pi's `get_state`, including after `/thinking` and model/session switches. While a prompt is active, the footer flower cycles through four flower shapes beside the working/thinking/writing/tool phase, including when Pi is silent; the header flower stays still. The chat transcript shows a compact, **up to three logical lines** of exploration status instead of one row per file: `◐ Exploring · latest: path` rotates a small one-cell glyph (`◐ ◓ ◑ ◒`) while exploration is active, even if Pi has no new event between reads. The path updates only when Pi opens a file; checked completion counts appear below as `✓ Read · N files` and (if applicable) `✓ Bash · N commands`. The Explore phase stays open while Pi is still working between reads or thinking; it becomes `✓ Explored · latest: path` only when Pi starts an edit/write or settles. The spinner stops as soon as Pi begins an edit/write, settles, or the read phase is interrupted. The Explore glyph and footer flower animate independently during an active run; the composer cursor stays visible in its steady style, and the Goal bar and counts do not animate. Only successful completions increase the checked counts. Failures and approval decisions stay distinct, and every successful edit retains its own bounded Pi-provided diff. Routine reads, bash starts/completions, and thinking phases do not add repeated chat rows. The footer reports Pi's current phase (Thinking only on Pi reasoning events), elapsed time, and Esc stop; bash arguments and raw reasoning remain hidden. No tool count is presented as a percentage.

Below the composer, the single footer row also shows the last **Pi-confirmed** session snapshot: `Ctx used/window · %`, cumulative session `In`/`Out` tokens, approximate cache-read tokens (`Cache ~value`), and approximate USD cost (at most two decimal places; positive costs below half a cent show `<$0.01`) when space allows. Cache-write tokens are deliberately omitted from this compact footer. Counts are displayed with decimal `K`/`M`/`B`/`T` suffixes (for example, `Ctx 200K/1M`, `In 12.3K`, or `/compact`'s `1M → ~200K`) to fit; labels are rounded for display only, while Pi's underlying counts are unchanged. Current activity stays left and an explicit Goal stays right; on narrow terminals, activity and Goal take priority over optional usage details. Hibiscus obtains these numbers from Pi's `get_session_stats` at startup and after completed runs, model/session/thinking changes and manual compaction. The snapshot stays steady while Pi is running; Goal updates do not trigger stats requests or attribute a cost to a goal. It does not infer context from tool calls or claim a live per-token counter while Pi is streaming. Pi may omit context usage or return null immediately after compaction; Hibiscus then shows no percentage rather than inventing zero. Token/cost totals are Pi's cumulative session accounting, not only the latest prompt and **not a provider subscription/quota balance** (Pi RPC does not provide that field). If an older Pi build does not support stats, the footer falls back to the ordinary hint without fabricating figures.

When Pi explicitly creates a numbered checklist with Hibiscus's `goal` tool (1–50 steps), the footer shows current activity on the left and `Goal  ███░░░  12/20 · 60%` on the right, on the **same row while Pi is working**. Pi can mark a step complete only by calling that tool for a specific step number; reads, edits, retries, and time elapsed do not automatically advance the bar. If Pi does not create a checklist, the right-hand Goal indicator is absent. The entire Goal indicator disappears when the run settles, leaving the normal idle input hint; the checklist stays in Pi's session for the next active run. Ask the agent to create an explicit checklist if you want measurable progress. Completed checklist state is stored with Pi tool results and restored when resuming the session. `/new` clears the displayed goal; ordinary standalone Pi is unaffected. This is a heartbeat even when the provider has not sent text. A heartbeat is **not proof the provider is making progress**; it means Hibiscus is still awaiting Pi.

The transcript renders common Markdown for readability without changing saved Pi messages. It shows concise tool start/finish events with read/write/edit file paths and success or failure. Raw thinking text and full tool results are not displayed. For a successful Pi `edit`, Hibiscus can show up to 40 lines of Pi's returned diff (context, additions, deletions); an unsuccessful edit or missing diff does not get a preview. The preview is not a replacement for reviewing `git diff`.

Scrolling stops at the oldest complete viewport instead of leaving most of the screen empty. When new output arrives while you are scrolled up, the view remains anchored until you scroll back to the bottom.

In full-screen mode, Hibiscus receives mouse button-motion reports and highlights drag selections in the **visible transcript** (not the composer or dialogs). Release or Ctrl+C with a selection requests a copy: small selections use `pbcopy` on macOS or `wl-copy`/`xclip`/`xsel` on Linux when available; otherwise Hibiscus sends a bounded OSC 52 clipboard request to the terminal. Some terminals/multiplexers block OSC 52, and no success notice is shown because it cannot be confirmed. A selection clears on scroll, resize, handoff or transcript changes; dragging past the viewport does not yet scroll/select off-screen text. Wide/combining Unicode may not align exactly because the renderer currently uses character rather than terminal-cell widths. PTY tests verify highlighting and OSC 52 bytes, **not** a physical clipboard change; verify in your terminal before relying on it. Plain/line mode retains the terminal's normal selection.

## Pi diagnostic warnings

In full-screen chat, Pi's stderr is collected rather than written directly over the editor. A compact amber `Pi:` diagnostic row uses the bottom row **below the composer and its status/Goal hint**. It does not move the composer, hide its cursor, alter the draft, or send anything to the model. Startup warnings remain visible while waiting for Pi metadata, and the row refreshes during idle input, active runs, pickers and dialogs, including resize/reconnect.

The summary retains up to four recent sanitized messages, newest first; repeats are counted, older entries are omitted, and long text is clipped to the terminal width. It is a recent diagnostic summary, not a complete log or a live authentication-status indicator. ANSI/control sequences are stripped, line storage is bounded, and common credential patterns are redacted on a best-effort basis—review screenshots before sharing. These messages are not RPC events and do not mark an agent run complete or change provider configuration. The underlying provider/model warning may still need attention.

One-shot, piped and line-mode output keep Pi's original stderr separate from stdout. Native Pi TUI handoff retains its own display while Hibiscus is suspended.

## Dangerous-command approval

`read`, `edit`, `write`, and ordinary `bash` commands run without a prompt. Before Pi's **agent** executes a recognized dangerous `bash` tool call (such as `rm`, `git clean`/force push, `sudo`, permission changes, publishing, shell indirection, or output redirection), Hibiscus shows the reason, working directory, and exact command. Use Up/Down or the wheel to choose **Deny** (default), **Allow** (once), or **Always Allow**, then Enter to confirm. Always Allow now grants the **patterns displayed inside the approval panel** for the current working directory and chat, not the exact prompt/message text. For simple commands the suggested pattern is a command/subcommand prefix such as `git push *`; `*` includes later argument changes, different destinations, and `--force`. Compound shell commands are reviewed by constituent commands; quoting, indirection and redirects that cannot be safely grouped fall back to exact-command grants. Comments outside quotes are ignored for matching. Review the displayed scope before choosing Always Allow. The grants are not persisted: session switch/new session, reconnect or restart clears them. Already-pending approvals covered by an Always Allow answer are skipped; Deny rejects waiting requests. This Hibiscus approval prompt has no idle timeout: it waits for an explicit decision. Esc, Enter on the default Deny row, dialog failure, and non-interactive use deny by default. If the terminal disconnects, do not assume the command ran; review the session before retrying. Approval details appear inside the docked panel rather than overwriting the composer. For long commands, use PgUp/PgDn to view the full details; Allow/Always Allow cannot be confirmed until the last detail page has been displayed. Line mode retains numbered prompts.

This is a **best-effort guard, not a sandbox**. Arbitrary scripts, indirect effects of seemingly safe commands, and `edit`/`write` can still change or remove files; command classification cannot prove a shell program is harmless. Pi remains responsible for tool execution and model behavior. Direct user shell commands and tools outside the four-tool allowlist are not covered by this approval gate. ## Errors and recovery

A rate limit, subscription/quota problem, authentication failure, or rejected command no longer closes interactive chat. Hibiscus shows bounded error details and guidance while retaining the transcript. Pi controls automatic retries; the composer becomes available after Pi settles, not at the first failed attempt. Tool and extension warnings do not automatically fail the whole run.

- **`/restore`** brings the last failed prompt and images back into the full-screen composer for review. Nothing is sent until you press Enter; earlier tool actions may already have happened.
- **`/reconnect`** recovers a disconnected Pi backend using the last confirmed session path. It never replays a prompt. If no path was confirmed, it explains that a new session will be opened.
- While disconnected, `/help`, `/restore`, and `/quit` remain available; other input is not sent.
- One-shot/piped failures still exit nonzero. Unusable terminal I/O and initial startup failures can still exit.

See [error handling and recovery](error-handling.md) for the event mapping, classification, limits, and regression tests.

## Updates

Prebuilt installs in full-screen mode check for a newer public GitHub release in the background at most once per day. When idle, the picker offers **Later** (the safe default) or **Update now**. A check never interrupts a draft in progress, and offline failures do not block chat. To check or update on demand, exit and run `hibiscus update`; see [Installation and releases](installation.md). Set `HIBISCUS_NO_UPDATE_CHECK=1` to disable automatic checks.

## Authentication handoff

In full-screen mode, `/login` offers **OpenAI Codex** or **another provider** regardless of the active model (which may be absent after logout). With Node.js and the matching Pi SDK available, choosing Codex stays in Hibiscus: select browser or device-code sign-in and wait for confirmation. On macOS, Hibiscus opens the validated browser sign-in URL with the system `open` command after you choose browser login, independent of terminal hyperlink support. The screen still shows **Open Codex sign-in ↗** as a short OSC 8 hyperlink where supported rather than a URL broken across rows. Press **Ctrl+Y** to ask an OSC 52-capable terminal to copy the complete URL. If the browser could not open and neither terminal feature works, cancel and retry using device-code sign-in. A browser callback can finish automatically; if it cannot reach WSL, paste the redirect URL into the masked composer instead. Press Esc to cancel. Once Pi's SDK reports login and credential storage complete, Hibiscus ends the dedicated helper itself; it does not wait for the browser tab or callback connection to close. The URL stays out of transcript text but still contains sensitive OAuth state; the device code is also short-lived and sensitive. Do not share screenshots of either. Pi handles credential storage and token refresh. On success Hibiscus reconnects its idle RPC child to the same saved session (or starts a fresh session if the chat is still empty). Ctrl+C is read as an input key while the terminal is in raw mode; use Esc to cancel the sign-in flow rather than expecting the shell's usual interrupt signal.

Non-Codex provider login, line-mode login, and login with an unavailable Node/SDK helper continue to use the **Pi TUI handoff**. No prior message is needed. Hibiscus closes its idle RPC child before Pi opens the saved session; for an empty chat Pi runs with `--no-session`. In Pi, run `/login`, then `/quit` to return. Hibiscus reconnects its RPC child afterward. Hibiscus never stores credentials itself.

### Logout inside Hibiscus

In full-screen mode, **`/logout`** lists providers with stored Pi credentials (OAuth or API keys), regardless of the active model. Choose a provider, then select **Remove stored credential** in the confirmation picker; **Cancel is the default**, and Esc cancels before removal. No saved chat is required.

Hibiscus uses Pi SDK `ModelRuntime.listCredentials()` and `logout()`—it does not edit `auth.json` itself. Only provider IDs and credential types cross the helper protocol, never tokens or API keys. After confirmation, Hibiscus closes the idle RPC backend before authorizing removal, then reopens the same saved chat (or a new empty session) so cached credentials are discarded. It also reopens after a helper error that might have occurred after mutation. Once removal starts, it waits for the bounded result rather than pretending cancellation can undo it.

This removes **one stored credential shared by Pi and Hibiscus**, not the conversation. It does **not** unset environment variables, change `models.json`, or revoke tokens at the provider. Those other credential sources can still provide access. If Pi removes the credential but reports a synchronization failure, Hibiscus reports that distinction and refreshes the backend.

With no stored credentials, nothing is changed. If Node/the compatible SDK is missing, or full-screen input is unavailable, Hibiscus explains the limitation without opening Pi automatically; run `pi` and `/logout` manually if needed. Piped input never authorizes logout. Real-provider logout is not exercised by the automated tests; they use an isolated fake credential store.

## Terminal compatibility

- Narrow full-screen terminals (under 60 columns) use one-cell side margins and a smaller transcript marker gap while retaining the `hibi` label once per assistant turn. The two header rows show a compact workspace label and model ID/available thinking level/session name (optional fields are omitted if they cannot fit). During an active run, the one-row footer shows complete activity text and `Esc stop` where space allows; if Pi provides a Goal it stays right on that row and optional usage is omitted. Idle Pi-confirmed metrics appear only as whole fields that fit. The composer remains fixed, grows with the draft and keeps the cursor visible; wider terminals retain their existing layout. Check Termius font size, actual columns and keyboard overlay when comparing physical screenshots; PTY tests cannot guarantee their rendering.
- In full-screen color mode, Hibiscus paints an Ubuntu-style aubergine (`#300A24`) behind the entire UI and keeps user-message rows slightly lighter. This does not change your terminal's configured default color; the original screen and style are restored on exit or Pi handoff. Terminals need 24-bit ANSI color support for the intended appearance.
- `NO_COLOR=1` disables ANSI colors, including the custom background; the terminal's own background shows through instead.
- `TERM=dumb` or a terminal smaller than the full-screen minimum uses line mode.
- Piped input produces plain output; it does not support Esc or interactive approvals.
- Pi extension dialog confirmations require an explicit `y` or `yes`. Non-interactive dialogs cancel safely.
- If a terminal's mouse or key escape sequences behave differently, use PageUp/PageDown and report the terminal name, WSL version, and a minimal reproduction. Do not attach private chat transcripts or credentials to a bug report.
