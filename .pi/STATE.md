## Agent-authored extensions, 2026-10-31

The owner corrected extension authoring: create an empty extensions directory during installation/startup, then let the agent create extensions and their chosen slash commands through native tools. The built-in extension-management slash workflow and fixed Python starter were removed. This work is included in the published v0.3.6 release above. Published v0.3.5 does not include the extension API or preceding structure refactor.

src/extensions owns global discovery, whole-manifest registration, offline schema compilation and the versioned executable protocol. Native create_extension accepts the complete manifest and arbitrary source files, validates before writing, exclusively creates private files and directories without overwrite, writes the manifest last and immediately publishes registrations. Native list_extensions reports directories, loaded tools/commands and errors; reload_extensions republishes manifests after native file edits. No implementation language or template is imposed. Source installer/startup creates HIBISCUS_HOME/extensions or ~/.hibiscus/extensions and preserves existing files. Workspace code is not auto-loaded.

Tools are namespaced as id__tool. Commands default to /id:command or choose a slashCommand such as /review; src/commands.rs shares native names across completion and collision checks. TUI display, Tab and Enter use one filtered native/extension catalog. CLI and TUI invoke the same custom commands. Unknown slash tokens stay local; absolute file paths with another slash remain prompts. Catalog snapshots are stable through each provider response/tool batch; agent creation/reload publishes registrations for the next provider request within the same conversation and metadata for the next user command. Agent authoring/inspection tool results enter normal session/model history; custom slash invocation is display-only and creates no provider request.

Extensions are trusted user programs with inherited access and no approval gate or sandbox. APIv1 writes one typed JSON request then stdin EOF and requires one matching-version/ID JSON reply. stdout/stderr are capped at 64 KiB each, requests at 128 KiB, arguments/input at 64 KiB, and runtime at 1–600 seconds. Shared src/process.rs provides concurrent bounded IO, process-group cancellation and reaping for native shell and extension tools. Tool results retain call IDs, actual OS exit/duration, logical error flags and optional metadata. Manifest/code failures leave interactive chat usable; extension errors guide to code rather than provider login. Creation checks current on-disk manifests, including edits earlier in the same tool batch, before writing. Source creation rejects traversal, conflicting paths, existing directories and command collisions before mutation. Capacity checks prevent new folders displacing existing registrations at discovery limits.

jsonschema 0.60.2 has default features disabled, including HTTP/file reference resolvers. Draft 7 schemas compile once with Rust regex; external references fail. examples/extensions/hello is optional author reference code, not a generated or embedded starter. No Pi/Node agent dependency, lifecycle hooks, arbitrary widgets, provider replacement or remote package management was added. See docs/extensions.md and docs/development/extension-architecture.md.

## Current implementation

Hibiscus owns its Rust agent loop, provider adapters, native file/shell/checklist tools, API-key and Codex OAuth stores, sessions, queues, compaction and terminal UI. It uses a bounded private in-process JSONL socket for presentation, with no Pi SDK, Node agent runtime or external credential/session import. Providers are configured for Responses, compatible Chat Completions and Anthropic Messages. Model IDs/capabilities are explicit config; unknown usage/context/pricing remains unknown.

Native tools run directly after validated arguments and authoritative provider completion. The approval system, slash command, preferences, grants and special dialogs are removed; old approval.json is ignored. Timeouts, cancellation, process-group cleanup, call/result IDs and unknown-outcome recovery remain. Tools are not sandboxed. The extension API is described above and is included in v0.3.6; it is separate from the published v0.3.5 source.

TUI remains the startup default with raspberry/aubergine styling and the solid slanted HIBI welcome. Active-model display follows credential availability; login selects the authenticated provider's configured model and logout preserves environment access. Login hints hide when credentials exist. /cli and /tui retain one runtime/session without resending prompts; CLI login/logout temporarily use native masked fullscreen dialogs.

CLI uses a dark background, compact metadata, grouped reads, green/red tool outcomes, actual shell output, measured duration/OS status, compact numbered edit previews and red/green diffs. /output latest/list/numbered inspection is local and read-only, with no provider call or tool rerun. Numbers refer to current active history; recent lists are bounded to fifty. Full saved bounded output and recorded edit diffs remain available across reopening that session; /new and compaction change active history.

CLI supports Enter-to-send, Alt+Enter/Ctrl+J newlines, arrows/Home/End/Backspace/Delete and atomic bracketed paste. Ordinary prompt whitespace is preserved. Invalid/oversized paste keeps the draft; CLI is capped at 64 KiB and TUI at 8 KiB. The editor repaints at most six draft rows plus a notice, using the existing terminal reader and locked unicode-width 0.2.2. NO_COLOR omits styling but interactive editing uses cursor/paste controls. TERM=dumb and nonterminal input retain the simple reader. Resize starts a fresh draft block on the next key. Paste mode is restored when leaving input and during cleanup.
