# Current state

## Native runtime migration, 2026-10-29

The owner approved migrating Hibiscus away from both the Pi SDK and Pi runtime after reviewing the draft. Implementation was prepared on `codex/native-runtime`, based on `7220347`. The owner explicitly authorized pushing this native migration and OAuth work to `origin/dev` on 2026-10-29. Source publication is limited to that branch; no new PR, release, npm publication, install or real-account mutation is included. Version remains 0.3.4; existing published assets are not established as native builds. Existing untracked `.agents/` is untouched.

Hibiscus now owns direct HTTPS/SSE provider connections, the model/tool loop, file/shell/checklist tools, shell approvals, API-key storage, sessions, compaction, cancellation and queues. `src/runtime/` replaces `src/pi/`; bundled SDK/JavaScript helpers and runtime/bootstrap/update logic are removed. The TUI adapter uses an in-process Unix socket, not an agent subprocess. Typed provider/session/tool/event data stay behind the adapter. Installer/updater manage Hibiscus only; Node is needed solely for the optional npm installer wrapper.

Providers: OpenAI Responses, compatible Chat Completions and Anthropic Messages. Provider endpoints/model IDs/capabilities come from native config. API-key entry is masked; stored keys use a private atomic auth file, with configured environment credentials taking precedence. Native Codex browser OAuth is implemented using the public-client legacy Codex protocol, independently of Pi. /login offers Browser Login → Codex and API Key → configured provider. Codex credentials use a separate private codex-auth.json file with atomic replacement and process-serialized expiry refresh. The fixed subscription Responses endpoint cannot be redirected in config; browser sign-in selects the configured Codex model. No Pi/Codex/Claude token store is read. A legacy codexContextWindow-only config fails with migration guidance rather than being silently repurposed. There is no automatic legacy session importer.

Native sessions use versioned JSONL in ~/.hibiscus/sessions, scoped to the canonical workspace. Missing tool results become unknown-outcome records on resume and are never replayed. Compaction privately archives original history before replacing active context. Native tools are read, write, edit, bash and goal. All bash calls require approval when enabled; Always Allow applies to the exact command for the run. Other file tools are not sandboxed. Supported Mermaid rendering is bounded linear top-to-bottom graphs; unsupported graphs remain source.

## Verification

- `cargo test --locked`: 136 unit tests and 24 native integration tests passed on this macOS host. The prior Pi-only process/helper fixtures were retired, not counted as native coverage; their source remains in Git history.
- Native HTTP fixtures exercise the actual binary through all three provider protocols, fragmented tool arguments, real temporary file/shell work, approval deny/grant, session resume, crash recovery, manual/automatic compaction, project instructions/skills, masked API-key login/logout, browser-menu cancellation, stream/shell cancellation, queue delivery and queued failure recovery. Native OAuth unit fixtures additionally exercise real loopback callbacks, PKCE/state validation, masked manual redirect handling, denial/cancellation, token exchange, refresh rotation and serialization, failed-refresh/account-change preservation and credential endpoint pinning. Codex response.done accepts tools only with completed status.
- A smoke test succeeds with Pi/Node/curl absent from PATH. An authoritative-completion test keeps the HTTP socket open and verifies the CLI still finishes. No real provider, credential or billable request was used.
- `cargo clippy --locked --all-targets -- -D warnings`, formatting and diff checks passed without lint allowances. Native installer fixtures, version-bump tests and offline npm package tests passed. CI/release publication was not requested or verified.
- Initial native adapter tests exposed cloned socket O_NONBLOCK flags affecting the reader; the reader now polls readiness instead of treating WouldBlock as EOF. A local HTTP test fixture also needed an explicit blocking mode on accepted sockets. Final native tests passed after these fixes.

## Remaining acceptance and compatibility limits

- Real provider/account behavior, Linux execution, release-target builds and physical-terminal clipboard/rendering acceptance are not established by local mocks.
- Provider catalogs and reasoning/image/context capabilities are explicit configuration, including Codex. The default Codex ID is gpt-6.1-sol, not a guarantee of account access; no live catalog discovery is claimed. Unknown token usage/context/pricing remains unknown. Confirmed Anthropic context includes cached input. Compaction scheduling is not an exact tokenizer or a provider budget guarantee.
- Live native Codex browser login, refresh and inference are not verified against a real account. The protocol reference is installed Pi 1.1.0's legacy Codex adapter using the public Codex client ID, not its separate dynamically registered ChatGPT flow. No user-supplied client ID is needed. Device-code login, Claude browser login, OS-keychain integration and legacy session import remain unavailable. API keys and Codex tokens use separate private mode-0600 files. Logout removes local credentials without remote revocation.
- Existing Unicode cell-width and off-screen transcript-selection limits remain. PTY output does not prove flicker-free presentation or actual clipboard changes.
- Historical profiling documents describe Pi-backed builds. Their mock-process launchers were retired; no native performance measurement is claimed.

Review README and docs/native-runtime.md before testing an existing installation. Keep old configuration/data backed up; do not alter real credentials merely to validate this migration. Publication requires an explicit action and destination request.
