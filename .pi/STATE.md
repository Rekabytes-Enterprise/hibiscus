# Current state

## Status

- Hibiscus now stages a bundled private Pi approval extension and launches its RPC and auth handoff children with `--no-extensions --extension <explicit approval.mjs> --tools read,bash,edit,write`. Pi's `tool_call` hook gates common dangerous bash commands before execution through the existing RPC select dialog: Deny (default), Allow once, or Always Allow for the exact command + cwd in the current session. Session switches/new sessions clear cached grants; restart clears them too. read/edit/write and ordinary bash are unchanged. Esc/empty/timeout, non-interactive use, and dialog failures deny. This is best-effort classification, not a sandbox; script side effects and unguarded file edits remain possible.

- Root `CHANGELOG.md` now includes the 0.1.6 changes and 0.1.0–0.1.5 history, with version-matched release links. The redesigned README links to the changelog.

- Full-screen `/new` now opens a blank local chat after Pi confirms session creation: no old transcript or command/confirmation lines remain, and composer/attachments, scroll, transient UI, and failed-prompt restoration state are cleared. The selected model is retained and Pi's new session status is fetched. Rejected/cancelled creation leaves the existing view intact; persisted session files and plain line-mode confirmation are unchanged.

- Full-screen `/logout` now stays in Hibiscus for all providers with stored OAuth/API-key credentials. `src/pi/logout.rs` and `logout.mjs` use Pi SDK `listCredentials()` metadata and `logout()`; users select a provider and explicitly confirm (Cancel default). The idle RPC child closes before removal is authorized, and the same saved session (or new empty chat) reopens afterward, including uncertain mutation failures. Cancel/empty stores/missing SDK do not change credentials or restart RPC. Missing SDK/Node or line mode explains how to use Pi manually rather than automatically handing off; piped input never authorizes removal. Environment/model-config credentials and provider-side tokens are unchanged. Only isolated fake credential stores were modified in tests.

- Interactive chat now catches recoverable provider/command failures instead of exiting. `src/pi/error.rs` supplies typed error sources/categories and bounded/redacted details; `src/pi/run.rs` replaces the sticky failure flag with final-outcome tracking across retries and compaction. Pi remains responsible for automatic retries. `/restore` stages failed text/images for explicit review; `/reconnect` recovers broken RPC connections using the last confirmed session path without replay. Transport/protocol failures show a disconnected footer and stop/reap the old Pi process group; local recovery commands stay available. Metadata requests have a 30-second response deadline; cancellation must settle within 10 seconds or the backend is disconnected. One-shot/piped errors still exit nonzero. Event mapping and limits are documented in `docs/error-handling.md`.

- README redesigned with a centered raspberry flower/terminal-chevron SVG logo, lowercase wordmark, live release/dev-CI/release-download badges, an explicitly labeled illustrated terminal preview, quick start, feature/shortcut/command tables, and links to detailed docs. Artwork lives in `docs/assets/`; no private screenshots or session content are included. The download metric counts all GitHub release assets (including checksums), not installs or unique users. CLI rendering is unchanged.

- Full-screen input now grows with newlines and wrapping to five rows, then scrolls with Up/Down or the wheel over the input rows. Ctrl+Enter (CSI-u/modifyOtherKeys or LF) and Ctrl+J insert a newline; Enter sends the unchanged multiline draft. The footer now advertises Ctrl+Enter, which the user confirmed works; Shift+Enter is accepted when distinguishable but sends in their terminal. Keyboard disambiguation is enabled/restored alongside the alternate screen. Editing remains end-of-draft only. Live turns now have exactly one blank row before the next user message.
- Full-screen image paste now advertises Pi's platform-default shortcut: Alt+V on WSL, Ctrl+V elsewhere. Both shortcuts are accepted, including CSI-u/modifyOtherKeys encodings; key-release events do not paste. The user reported Ctrl+V did nothing; inspection confirmed Pi uses Alt+V on WSL, whereas Hibiscus previously only accepted raw Ctrl+V. Image paste stages clipboard images with a border attachment count; Ctrl+X removes staged images and Ctrl+C clears the entire draft. Image-only and text+image prompts use Pi RPC `images` blocks; live/history display shows placeholders, never base64. Clipboard reads run asynchronously with cancellation, five-second per-command deadlines, helper process-group cleanup, and a 10 MiB/image, four-image limit. Backends: macOS AppKit via osascript, Windows clipboard via PowerShell in WSL, wl-paste on Wayland, xclip on X11. A real WSL PowerShell diagnostic confirmed the current clipboard contains an image and the implemented extraction returns PNG-signature bytes below the size limit (no image contents logged or saved). The user confirmed Alt+V image paste works after rebuilding. Provider image interpretation and real macOS clipboard behavior still need verification; PTY tests mock the helpers and Pi.
- Chat now shows a visible `hibi` heading above agent replies and a subtle raspberry-gray background across each full user row, including wrapped lines and margins. `/sessions` and resumed history now correctly distinguish users from agents (the interactive history path compared the display label `you` against `user`). Plain piped history remains unchanged; `NO_COLOR` omits the tint.

- `src/main.rs` owns CLI arguments; `src/chat/` handles chat, models, and sessions; `src/pi/` owns the long-lived Pi RPC child/protocol and extension dialogs; `src/tui/` owns input and rendering. Hibiscus now launches both Pi RPC and auth-handoff TUI with `--no-extensions --extension <bundled approval gate> --tools read,bash,edit,write` to retain built-in tools and the explicit approval gate without starting Pi-installed extensions (including an MCP bridge); normal standalone Pi remains unchanged. `docs/` and `CONTRIBUTING.md` document these boundaries and development workflows. Sessions persist in Pi; `/new`, `/quit`, `--continue`/`/continue` (latest session), and `--sessions`/`/sessions` work without restarting the process for in-chat switching. One-shot prompts are still saved as separate sessions.
- Resume and switches show up to the last five user turns and their assistant text via Pi `get_messages`; the picker reads Pi's persisted JSONL files for the current workspace.
- Interactive terminal chat uses raw-mode `/dev/tty` input for Esc cancellation and Pi extension dialogs (`confirm`, `select`, `input`, single-line `editor`). The reader now uses a separate nonblocking open and bounded `select` waits, preventing blocking reads from trapping handoff shutdown. Auth PTY fixtures share a bounded, deadline-driven harness with process-group cleanup and captured-output diagnostics. Non-interactive dialogs cancel rather than approve; Esc clears queued messages and aborts the current Pi run.
- `/models` now lists all Pi-configured models as `provider/model`, sorted by provider then ID, and switches providers/models via Pi RPC without reauthenticating. Full-screen selection uses a five-row picker (`src/tui/picker.rs`, reused by `/sessions`) docked above the composer and aligned with its outer margin, with active model marker, arrow/wheel/PageUp/PageDown navigation, Enter selection, Esc cancellation, and a moving viewport/scrollbar. Typing `/` in the composer opens live prefix-filtered suggestions for supported Hibiscus commands (`src/chat/commands.rs`); Up/Down/wheel navigate, Tab completes, Enter runs, Esc dismisses. Line mode retains numbered input. In full-screen mode `/login` now offers an explicit Codex/other-provider picker regardless of the active model, which may be absent or different after logout. Codex uses `src/pi/auth.rs` and the embedded Node helper (`codex-auth.mjs`) for Pi's SDK OAuth flow and reconnects the idle RPC child on success. Browser sign-in now opens the validated URL via macOS `/usr/bin/open` after the user chooses browser login, rather than relying on terminal OSC 8 support; the OSC 8 short hyperlink and optional Ctrl+Y OSC 52 clipboard request remain as fallbacks without exposing the URL as wrapped transcript text. The mock SDK PTY suite tests browser completion, device selection, masked manual input, empty chats, cancellation, and same-session reconnection. The post-login freeze was reproduced in a live user run: browser showed OAuth success while Hibiscus remained in `/login`. Process inspection found Hibiscus blocked waiting for the Node helper, which retained an established localhost callback socket after closing its listener. Auth now treats the helper's completion event as authoritative and terminates/reaps it rather than waiting for browser connections to close; a local-socket PTY regression covers this. Other-provider login and login with unavailable Node/SDK still hand off to Pi's TUI; Hibiscus now closes the RPC child before the handoff, opens Pi on the saved session or `--no-session` for an empty chat, and reopens the RPC child afterward. Neither auth path requires a saved chat message.
- `dev` was pushed at version `0.1.6` (commit `e880d84`) in `Cargo.toml`/`Cargo.lock`, release documentation, and the installer fixture. `scripts/bump-version.sh` performs future coordinated version bumps using Cargo's workspace-only lockfile update; its sandbox regression covers bumping, invalid versions, and rollback. Mock updater releases derive a version newer than the current package, so subsequent version bumps do not break those tests. `install.sh` provides checksum-verified prebuilt installation and atomic replacement to a user-writable directory for Linux musl and macOS on x86-64/ARM64. The prebuilt installer now finds or installs Pi if missing: from the official npm package in a user-writable prefix when compatible Node/npm are available, otherwise via Pi's official HTTPS installer (which may prompt for Node). It verifies Pi runs and links a Pi launcher beside Hibiscus if needed. Pi's installer may prompt to bootstrap Node.js; Hibiscus discovers its standalone Node at startup even if the user's shell PATH has not been refreshed. Source/Cargo installs still require Pi separately. A managed Pi linked into the install bin directory remains eligible for Codex SDK auth. `hibiscus update` checks the latest public GitHub release, compares strict version tags, invokes the embedded installer for a pinned version, and refuses unrecognized install locations or symlinks. Full-screen prebuilt installs check in the background once a day and offer a Later/Update now picker when idle; offline checks never block chat. `HIBISCUS_NO_UPDATE_CHECK` disables automatic checks. `.github/workflows/ci.yml` checks formatting, Clippy with warnings denied, and installer behavior on Ubuntu, plus Rust tests on Ubuntu and macOS for pushes/PRs to `dev` only; `main` does not trigger CI. `.github/workflows/release.yml` repeats quality checks, builds all four targets, ad-hoc signs macOS binaries, generates `SHA256SUMS`, and publishes tagged GitHub releases. `hibiscus --version` supports installation checks; `tests/install.sh` covers Linux/latest and macOS/version-pinned selection with mocked downloads.
- Interactive chat uses an alternate-screen display (`src/tui/screen.rs`) with a fixed composer, raspberry-pink flower accents, short Pi model/session status, and Markdown-formatted transcript (`src/tui/markdown.rs`). While a prompt is active, the flower cycles and a raspberry-pink footer shows working/thinking/writing/tool phase and elapsed time even if Pi is silent. RPC tool start/end events show themed read/write/edit paths and success/failure, plus a reasoning-duration note. Successful built-in edits display a bounded, color-coded preview sourced from Pi's `result.details.diff`; failures show no diff. Raw reasoning and other full tool results remain hidden. Mouse-wheel and PageUp/PageDown scroll while idle or streaming; the viewport stays anchored as new text arrives and stops at the oldest full page, not an almost-empty screen. Pi's original Markdown and session history are unchanged. The terminal screen is restored on exit/auth handoff; `src/tui/ui.rs` handles transcript labels and line-mode fallback. Piped input/output remains plain.
