# Durable project memory

Keep enduring decisions and evidenced pitfalls here. Current work, unresolved reports, hypotheses and test runs belong in `STATE.md`; release history belongs in Git and `CHANGELOG.md`. These records never replace reading the affected code.

## Evidence discipline

- **Implemented is not verified.** Code inspection proves an implementation exists. Unit/mock/PTY tests prove only their scenarios. A terminal screenshot or user confirmation applies only to the behavior/build observed, not every platform or a later revision.
- Record test commands, outcome, environment and snapshot in STATE. Do not accumulate a diary of passing test counts or copy feature descriptions into MEMORY. A source change makes earlier verification historical.
- Keep a user-reported bug open as “candidate fix, retest pending” until the relevant reproduction has been checked. A green suite does not override a later user report. Say exactly what was tested; avoid blanket “works,” “fixed,” “safe,” or “identical to Pi” claims.
- Separate facts from hypotheses. Promote a cause/fix to durable memory only with code evidence and a reproducer/regression where feasible. Merge by root cause rather than adding an entry for each recurrence.
- Preserve the agreed behavior when changing UI: show a draft/mockup when asked, make targeted changes, and test regressions in adjacent flows. Do not silently substitute hiding the cursor for making it steady.
- Never commit credentials, auth URLs/codes, private screenshots/transcripts, or user-specific machine configuration. Use synthetic fixtures. Do not mutate real provider credentials merely to run verification.

## Architectural boundaries

- **Pi owns the agent.** Hibiscus is a Rust client of a long-lived `pi --mode rpc` child, not a second agent, retry engine, credential manager, or session database. `src/chat/` owns workflows, `src/pi/` integration, and `src/tui/` presentation. Map: `docs/architecture.md`.
- **Protocol:** strict LF-delimited JSONL on RPC stdout; diagnostics stay on stderr. In a full-screen alternate-screen chat, copying child stderr to the terminal overwrites the composer/footer (Pi model-scope warnings reproduced this); drain continuously into a bounded, sanitized and deduplicated bottom diagnostic row instead. Never parse diagnostics as RPC or send them to the model; keep plain/piped stderr unchanged. Reuse the UI feed across reconnects and poll it during startup metadata waits, idle typing, streaming and dialogs. Regressions: `tests/diagnostics_tty.rs`, `src/pi/diagnostics.rs` unit tests. Correlate responses by ID. Prompt acceptance is not completion; `agent_end` can precede retries/recovery/queued work. Use `agent_settled` for run completion. Unknown event types are not inherently errors. Buffered command serialization must disarm `BufWriter` on failure: its Drop can otherwise retry an uncertain write. Regression: `buffered_command_does_not_retry_a_failed_write_on_drop`. Borrow image payloads during serialization and move response data instead of duplicating large JSON values. Evidence: `src/pi/rpc.rs` tests and `src/pi/run.rs`.
- **Transport overload:** do not put a blocking bounded channel behind a synchronous Pi stdin writer: a peer filling stdout before reading stdin can deadlock both pipes. `pi/transport.rs` uses raw-frame byte/count budgets and explicit connection invalidation on overload, plus nonblocking writes with deadlines and input servicing. This is fail-fast protection, not transparent flow control or a total RSS bound. For ignored tool-update `partialResult`, `RawValue` alone does not fully validate JSON string escapes (e.g. lone surrogates): walk the raw subtree with normal string decoding before dropping it. For user `message_start`, Hibiscus needs delivered text and image count, not echo base64: borrow/validate image-block `data` before dropping it; preserve assistant/user message ends, metadata and unknown blocks/events fully. Preserve malformed-field failures even for earlier duplicate keys. Regressions: `unused_tool_update_is_validated_without_building_partial_result`, `user_message_start_preserves_delivery_text_and_count_without_image_bytes`, `malformed_image_echo_invalidates_inbox_before_next_event`, `every_other_record_retains_full_value_and_correlation`. Never append abort bytes to an incomplete JSONL record; disconnect with uncertain delivery and require explicit review. Validate slow consumers, duplex floods, modal approvals, cancellation and large-image sends (`transport` unit tests, `tests/rpc_pressure.rs`; limits in `docs/rpc-transport.md`).
- **Queues:** send explicit steering/follow-up behavior through Pi, not a separate local scheduling loop. A queue acknowledgement is not delivery. Pending UI and transcript insertion are distinct; user-message events are the delivery signal. Preserve newer typing on rejection and never automatically replay an uncertain request after disconnect. Failed queued writes and the newest unacknowledged submission on receive failure use the single explicit `/restore` slot; do not describe this as recovery of every accepted Pi queue entry. A delayed queued response after the final `agent_settled` must not reset the settled flag: acceptance is not a new run, and the response branch must check completion before continuing (it otherwise skips the common completion path and hangs without another event). Only Pi's `agent_start` reopens run settlement. The explicitly requested `/loop` mode is a separate opt-in controller that submits sequential Pi prompts **after** settlement; it must not locally schedule steering/follow-up entries or treat a queue acknowledgement as completion. Regression: `tests/queue_order_tty.rs` (`accepted_steering_ack_after_final_settlement_does_not_hang_or_replay`, `late_ack_still_waits_for_a_nonempty_pi_queue_to_drain`). Text-matching identity limitations remain in STATE. Evidence: `tests/steering_tty.rs`.
- **Errors:** distinguish request failures from transport/protocol failures. Interactive request failures should retain chat; one-shot/piped failures keep nonzero exit status. Successful Pi retries must supersede earlier failed attempts, not inherit a sticky failure flag. Provider-string categories are advisory hints only; quota/billing can also be HTTP 429. Evidence: `src/pi/error.rs`, `src/pi/run.rs`, `tests/error_recovery.rs`; limits in `docs/error-handling.md`.
- **Thinking and manual compaction:** Pi is authoritative for model-supported thinking levels (`get_available_thinking_levels`, `set_thinking_level`, then `get_state` to confirm) and for manual `compact` summary/session persistence. Never send built-in TUI commands as RPC prompts. `compact` returns only after a model call; it needs a distinct long-running, ID-correlated response loop instead of the 30-second metadata deadline or `agent_settled`. The UI's thinking label and context/input/output/cache-read/cost snapshot must come from Pi's `get_state`/`get_session_stats` at confirmed idle boundaries (startup, completed runs, model/session/thinking changes and manual compaction), not local token accounting or a claimed subscription balance. Keep stats steady during active runs; Goal calls update the checklist, not token/cost accounting. The user found mid-run stats refresh distracting, so do not reintroduce it implicitly. `tests/context_tty.rs` checks the idle-only request order, Pi-backed values, Goal placement, null post-compaction context, and older Pi stats rejection. Abbreviate only displayed footer/compaction-notice token counts with decimal K/M/B/T; display cache reads as `Cache ~value` and omit cache writes from the compact footer. Format displayed USD cost to two decimals; positive values below half a cent use `<$0.01` rather than misleading `$0.00`. Never mutate Pi's exact values; test rounding boundaries so 999,950 is shown as 1M rather than 1000K. Context usage may be null after compaction; older Pi can reject stats, in which case show no invented values. Keep activity left and explicit Goal right in the one-row footer. Esc cancellation must drain both the compact response and abort acknowledgement (or disconnect with uncertain outcome); typed drafts must not become steering during compaction. Regression: `tests/pi_commands_tty.rs`.
- **Sessions:** Pi is the persistence authority. Clear the local `/new` view only after successful creation; rejected/cancelled creation must retain it. Do not delete saved sessions to clear the screen. Resume renders recent visible user/assistant text, not system/tool/thinking content or image data. Session-title caching is bounded, process-local and disposable; validate file identity/size/mtime/ctime, expire periodically, and invalidate deletions/replacements/workspace changes. Full-screen `/sessions` and `/continue` may scan those Pi files on a cancellable worker, but cancellation must not join a worker blocked on filesystem I/O or send a prompt; buffer typing in order and never replay Enter after loading. Line-mode/startup listing remains synchronous, and cold filesystem work is not faster. Do not stop scanning at the first prompt: later records can rename a session. Regression: `cache_reuses_unchanged_files_and_invalidates_rename_replace_delete_and_scope`. Evidence: `tests/chat.rs`, `tests/in_chat_sessions.rs`, `tests/new_session_tty.rs`.

## Tools, auth and sensitive data

- **Explicit integration only:** disable Pi extension discovery and explicitly load Hibiscus's bundled extension with a tools allowlist. A tools allowlist alone does not prevent installed extensions/MCP startup. The worktree includes `goal` alongside `read,bash,edit,write`; inspect `configure_builtin_tools` before changing flags. Identity and operational-clarification guidance belong in the explicitly staged extension's `before_agent_start` hook: present Hibiscus as the terminal interface powered by Pi, disclose real provider/model when asked, and guide the model to inspect safely and ask before materially ambiguous work without stalling on minor reversible choices. This is model guidance, not deterministic enforcement. A real macOS report showed `systemPromptOptions.sections` can be undefined; never dereference it without checking. Use structured sections when supplied, otherwise append to the existing rendered Pi prompt (or its append option on options-only hooks), preserving the base instructions. Returning `systemPrompt` on legacy hooks forces the full original-plus-guidance text for that run; it is not the preferred structured path. Neither guidance nor mock tests guarantee a model's literal wording or clarification behavior. Regression: `tests/approval.mjs` covers all three hook shapes. Do not alter standalone Pi's global settings to implement repository behavior.
- **Approvals:** enforcement belongs before execution in Pi's `tool_call` hook, not in the later `tool_execution_start` notification. Deny/Cancel must be defaults; absent UI, Esc, dialog failure or any explicit timeout must not authorize a flagged operation. The bundled Hibiscus approval prompt deliberately supplies no timeout: wait for an explicit decision without changing Pi's unrelated dialog timeout handling. Full-screen modal and line-mode reader must not invent a 60-second fallback. Per explicit user decision, Always Allow may grant broad displayed command/subcommand prefixes (`git push *` covers force and other destinations) within the current cwd and session. Never widen without showing the pattern being authorized; parse simple compound shell calls individually, keep complex syntax exact, and serialize parallel decisions so queued matches reuse an Always Allow answer while Deny rejects waiting requests. Clear grants on session changes/reconnect; no durable approval store. The user-authorized `/loop` uses a private staged `loop-active` marker to bypass only this Hibiscus `bash` gate; an RAII guard must remove it on completion, Esc, error and disconnect. Regression: `tests/loop_approval.mjs`, `tests/loop_tty.rs`, `tests/loop_stop_tty.rs`. This best-effort regex plus conservative shell scanner is **not a sandbox** and cannot certify arbitrary shell behavior. Evidence: `src/pi/approval.mjs`, `tests/approval.mjs`, `tests/approval_tty.rs`.
- **Goal display:** percentage must come from an explicit checklist, not tool counts, elapsed time or an invented estimate. It is model-reported progress, not independent verification of work. Store/reconstruct checklist snapshots through Pi's session data. Default `/loop <goal>` is a thin Pi-driven controller with skill-style testing instructions: keep the original request in continuations and accept `loop_status candidate_complete` as **model-reported**, not independently verified. No extra reviewer call, fixed test names or artifact schema is required. Shared failure-report guidance in both modes/continuations should request Playwright failure capture **before** the first browser test (guided `only-on-failure`, strict `on`, traces and optional failure video), without replacing unrelated app config, then preserve the original screenshot and save separately labelled annotations of failed controls, expected/actual behavior and post-fix screenshots; do not misrepresent overlays as original UI or introduce artificial bugs unless requested. This is model guidance, not proof of annotation execution. `/loop --strict <goal>` explicitly opts into the evidence and reviewer checks below. Both modes use the bundled `loop_status` structured result for completion/blockers, never raw assistant sentinels; bypass cleanup and Esc behavior are shared. Outside the private active loop marker this tool cannot authorize completion. In strict mode, the first named checklist remains provisional until a separate reporting-only call through Pi's selected SDK judges its scope covered. A missing-scope verdict lets the model expand it; then lock named steps so renaming/removing them cannot satisfy completion. Reviewer output must be exactly one native `submit_verdict` tool-call argument object, validated locally against the schema; asking for JSON prose alone is not reliable structured output. Use Pi's `strict: prefer` sampling with normal tool-call fallback, one bounded format-only correction with unchanged evidence, and no tool executor. Check `stopReason` first: Pi may resolve error/aborted messages instead of throwing, and truncated/deferred responses must not count as verdicts. Never require a custom Pi fork or change global settings for this helper. Regressions: `tests/loop_verify.mjs` and `tests/loop_tty.rs`. Reviewer failure/malformed output blocks rather than passes with safe failure categories; a `met` verdict with missing machine-checked UAT evidence is `not_met`, not a generic reviewer failure. This extra provider call may not appear in Pi's ordinary session stats. A machine-checked Playwright JSON reporter must show a passing, non-skipped test with a matching title and nonempty screenshot/console attachments for each step, followed by a successful Pi image read of a reported screenshot. Prefer `loop_status submit_evidence` with project/report paths to relying on bash command prefixes or complete stdout: wrapper commands and truncation can conceal a valid report. Resolve report artifacts relative to project/report directory; regular report reads are bounded to 4 MiB, and timestamp freshness is heuristic (one-second filesystem tolerance). Retain accepted packages and their counts with explicit stale reasons. Saved-report source fingerprints (bounded web-source/config inventory, excluding generated output/dependencies) distinguish actual tracked changes from subsequent wrapped log/server inspections; this is not universal runtime-dependency tracking. Playwright attachments can use inline base64 `body` or `path`, and multiple attachments may share a name: consider all matches rather than rejecting the first body-only screenshot and overlooking a later file. Validate bounded inline bodies and let image reads match decoded bytes or any recorded screenshot path. `submit_evidence` uses a private extension-UI bridge for immediate validation feedback, without human prompting. Send bounded console/test-source/historical failure excerpts and validated metadata to the reviewer, not just a boolean and prose. Do not claim pixel inspection from metadata. Regressions: mixed inline/file attachment tests, retained-stale counts, source fingerprint tests and the evidence bridge PTY fixture. Regression: `saved_report_survives_wrapped_command_truncation_and_readonly_log_checks` in `tests/loop_tty.rs`, path/freshness tests in `src/tui/loop_evidence.rs`. Assess **all** steps in one pass, present checklist and verified UAT counts separately, and send Pi the consolidated missing work. Repeated completion-only turns without tool work/new evidence can trigger targeted recovery then a stalled blocker; fold their local display only, never rewrite Pi's saved messages. This checks artifacts and coverage labels, not whether model-generated tests really assert the original user's intended semantics. Evidence: `goal` in `approval.mjs`, `tests/approval.mjs`, `tests/goal_tty.rs`, `src/tui/loop_evidence.rs`, `tests/loop_tty.rs`.
- **Auth boundary:** login/logout are not ordinary RPC prompts. Use the selected Pi installation's SDK for supported inline flows; Pi owns storage and refresh. An absent/different active model must not prevent choosing a stored provider. Logout removes stored credentials only, not environment/config credentials or provider-side access. Close the idle RPC writer before authorized logout mutation and reload it afterward, including uncertain post-mutation failures. Evidence: `src/pi/auth.rs`, `src/pi/logout.rs`/`src/pi/logout.mjs`, `tests/codex_auth.rs`, `tests/logout.rs`.
- **Helper completion pitfall:** OAuth helper `done` is authoritative. Waiting for natural process exit can hang on retained browser callback sockets. Terminate/reap the dedicated helper after the result; a deliberate cleanup kill must not overwrite reported success. Regression: `completed_login_reconnects_without_waiting_for_browser_connection_to_close`.
- **Terminal handoff:** stop/join the input reader and restore terminal state before handing ownership to Pi; avoid concurrent Pi session writers. Reconnect the saved session when known. Tests: `tests/auth_handoff.rs`. Failed/unknown request outcomes must not be silently replayed.
- **Clipboard:** WSL's Pi default is Alt+V; other platforms use Ctrl+V. Terminal interception can prevent Ctrl+V reaching Hibiscus. Clipboard reads are explicit, bounded and cancellable; send image content through Pi RPC, never base64 in visible chat. Staged images use immutable `Arc<Value>` handles: cloning for recovery must share the image, not copy its base64; serde's `rc` support preserves the Pi JSONL image shape. Incoming user `message_start` image echoes are validated without materializing base64; authoritative message ends/history remain separate allocations. Regression: `rejected_image_is_shared_between_live_draft_and_restore_slot` and image/steering PTY suites. Tests: `tests/image_paste.rs`, clipboard module tests. Clipboard-using fixtures must shadow every platform reader (`osascript`, `powershell.exe`, `wl-paste`, `xclip`) and assert which mock ran. Setting `WAYLAND_DISPLAY` does not select Wayland on macOS: the macOS branch chooses `osascript` first. A Wayland-only mock lets macOS tests access the runner's real clipboard, producing attachment timeouts unrelated to the behavior under test. Regression: `clipboard_fixture_covers_all_platform_readers` and platform-reader log assertions in `tests/steering_tty.rs`. Do not interpret mocked helper success as real desktop support. The transcript **copy** fixture must also shadow `pbcopy` on macOS (and `wl-copy`/`xclip`/`xsel` if a display is present): unlike Linux, the macOS copy path attempts `pbcopy` even with DISPLAY unset. Otherwise an OSC 52 fallback assertion can fail after reaching the runner's actual clipboard. Regression: `tests/selection_tty.rs` verifies use of a failing fake `pbcopy` and terminal-copy fallback without real clipboard access.

## UI and testing contracts

- **User preferences:** visible steady composer cursor, movable editing, aubergine background, flower/Explore activity indicators separate from the cursor, and live status left/explicit Goal right on one footer row. During streaming, distinguish waiting input from delivered chat. These are requirements, not claims of flawless rendering.
- **Rendering:** preserve `NO_COLOR`, plain piped output and terminal restoration. Cached row-diff output must invalidate on resize/resume or untracked terminal writes. Synchronized output needs balanced release on error/exit; keep a fallback for incompatible terminals. Cache transcript layout independently of row-diff painting; output-frame counts alone do not bound parser work or input latency. Use the same terminal-relative content width (two-column margins normally, one below 60 columns; no 100-column cap) for transcript, composer navigation, rendering, panels and cursor after resize. Regression: `wide_terminal_and_resizes_expand_composer_without_losing_draft`. Cache at explicit role-reset boundaries (not arbitrary lines) to preserve fences/table lookahead, invalidate on content/timeline/width changes, and apply coalesced scroll row deltas once at layout time. Printable input batches must stop before controls and preserve partial UTF-8. **Pasted newline is not submit:** Pi enables bracketed paste `?2004h` and buffers `CSI 200~ … CSI 201~` as text; Hibiscus must do likewise on its own TUI (Pi RPC cannot parse the user's terminal input). Carry partial paste across idle/active input, including metadata polling; disable the mode on exit/handoff, normalize CRLF/CR, bound the buffer and never submit a partial/invalid paste. If a terminal fails to bracket paste, a raw CR is indistinguishable from Enter; do not guess intent from timing. Regression: `tests/multiline_tty.rs`, `bracketed_paste_is_literal_and_bounded_during_an_active_run`. At fewer than 60 columns, keep full-screen composer/cursor and speaker roles; reduce margins/gap consistently across Markdown layout, mouse-selection coordinates and rendering. Prefer complete optional header/footer fields over clipped fragments; preserve activity left and explicit Goal right on one row. Regression: `tests/mobile_tty.rs`, `narrow_transcript_selection_uses_reduced_margin`. A PTY byte assertion cannot prove absence of visual flicker. The opt-in `/loop` remains active across multiple settled Pi turns and reporting-only reviewer calls: keep a separate loop-phase footer until the controller really exits, rather than showing idle `Enter send` whenever `Rpc::command` calls `stop_work()`. Regression: `tests/loop_tty.rs` checks the review footer and exit restoration. Evidence: Markdown/layout/batching unit tests, `tests/performance_tty.rs`, `src/tui/paint.rs`, `tests/rendering_tty.rs`, `tests/working_cursor_tty.rs`.
- **Fullscreen copy boundary:** Enabling `?1000` SGR mouse reporting in an alternate screen can divert terminal mouse selection to the app; handling wheel reports alone does not restore drag-to-copy. Pi regular mode delegates selection to terminal scrollback; its fullscreen mode enables button motion and owns selection. Hibiscus now handles SGR press/drag/release for visible transcript rows, highlights the range, and requests clipboard copy using local short-text tools or bounded OSC 52; do not show a success claim for unverifiable OSC 52. In full-screen idle mode, Ctrl+C must prefer copying a current selection; otherwise the first press clears the draft and arms a short, visible confirmation before the second press exits. Disarm on other input/timeout, keep Ctrl+C non-exiting during an active run and Esc for abort; preserve Ctrl+D and `/quit`. Release mouse modes during handoff/exit. Regressions: `tests/selection_tty.rs`, `sgr_drag_release_and_wheel_are_distinct_from_escape`. Physical-terminal copy and off-screen/Unicode selection limits are tracked in STATE.
- **Dialogs:** full-screen prompts must use the shared modal component, not raw writes over the composer. Preserve drafts, response IDs and safe defaults; display long command details without silent omission. Current bottom-page review tracking is not proof of complete human review. Evidence: `src/tui/modal.rs`, `tests/modal_tty.rs`.
- **Tool display:** use Pi tool-call IDs for lifecycle correlation and Pi `result.details.diff` for successful edit previews. Never invent a diff from requested edits or show a failed edit as successful. Do not expose raw reasoning or routine bash arguments. Approval review necessarily displays the command being authorized. Tests: `tests/tty.rs`, `tests/goal_tty.rs`.
- **Terminal-reader pitfall:** use a separate nonblocking open for the stoppable `/dev/tty` reader. `try_clone` shares file-status flags; changing nonblocking mode can affect the output handle. Bound waits, stop and join before handoff. During active RPC runs, signal a shared generation/condition variable **after** enqueuing terminal bytes or Pi frames; snapshot generation before polling queues to avoid lost wakeups. Notification is only a hint, never an authorization/completion signal; retain the timed animation/cancellation fallback. Evidence: `scripts/profile-wake.py`, `activity_notification_before_wait_is_not_lost`, steering/rendering/handoff suites. Regression: `idle_terminal_reader_stops_without_an_extra_keypress`.
- **PTY fixtures:** explicitly set TERM and window dimensions, drain output concurrently, and bound waits/cleanup. A PTY alone does not ensure full-screen mode. Prefer `tests/support/` to sleep-based drivers. Row-diff output requires a reconstructed view; previously displayed text is not proof of a new response or settlement. Use distinct response markers and the correct idle/event boundary.
- **Fixture paths:** canonicalize temp roots (macOS `/var` and `/private/var` can differ). Use atomic IDs plus exclusive directory creation, not clock+PID alone, for parallel fixtures. Regressions: `tests/pty_harness.rs`, `tests/in_chat_sessions.rs`.
- **Memory measurement:** separate Hibiscus from Pi/mock PIDs and exclude pre-exec harness memory. Linux `VmHWM` is approximate and sampled `smaps_rollup` RSS can miss short peaks; neither is a logical live-heap count. Queue wire-capacity budgets exclude decoded JSON trees and image recovery copies. Residual RSS after dropping values is not, by itself, evidence of a leak. Use distinct post-response state markers for phase boundaries, not stale idle-footer text. Reproducers: `scripts/profile-memory.py`, `tests/profile_memory.py`, `benches/allocations.rs`; measured results belong in `docs/memory-profiling.md`/STATE.
- **Build prerequisite:** minimal Ubuntu/WSL needs a C linker (`build-essential`), not only Cargo. Record a tooling blocker rather than claiming tests passed.
