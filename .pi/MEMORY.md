## Decisions

- **Release distribution:** Publish checksum-verified prebuilt archives for `x86_64`/`aarch64` Linux musl and macOS from version tags matching `Cargo.toml`. `install.sh` detects the target, verifies `SHA256SUMS`, installs to `${HIBISCUS_INSTALL_DIR:-$HOME/.local/bin}` without `sudo`, and supports version pinning. Linux musl keeps binaries broadly portable; macOS archives are ad-hoc signed but not Developer ID signed/notarized. CI on pushes and pull requests to `dev` (not `main`) enforces rustfmt, Clippy with warnings denied, installer tests, and Rust tests on Linux/macOS; the release workflow repeats quality checks before publishing. Its artifact-only publish job has no checkout: set `GH_REPO=${{ github.repository }}` alongside `GH_TOKEN` so all `gh release` commands resolve the repository without a local `.git` directory. `hibiscus update` (`src/update.rs`) compares numeric version tags from the public GitHub `/releases/latest` API, then runs the embedded, checksum-verifying `install.sh` pinned to that tag; never execute a remotely fetched shell script. Stage on the installation filesystem and rename the replacement atomically, rather than truncating the running executable; refuse symlinks and binaries outside the default `~/.local/bin` or explicitly set `HIBISCUS_INSTALL_DIR`. Full-screen prebuilt installs offer an opt-out-able, once-per-day background update check; CLI `update` checks each time. Regression tests: `tests/install.sh`, `tests/update.rs`. PTY integration tests must pass mutable null pointers to `libc::openpty` and cast `TIOCSCTTY` to `libc::c_ulong`; Linux accepts the looser forms but macOS libc signatures do not. Anonymous `curl` requires a publicly readable repository/release; private distribution requires authenticated downloads.

- **Backend boundary and sessions:** Hibiscus is a Rust CLI client for Pi RPC, not a port of Pi's TypeScript SDK. Pi owns agent runs, models, tools, auth, and persisted chat sessions. The SDK runs in Node.js/Bun; RPC is Pi's language-independent integration. For Hibiscus-launched Pi processes, apply `--no-extensions --tools read,bash,edit,write` to both RPC and auth-handoff TUI (`src/pi/mod.rs`): a tools allowlist alone does not prevent installed Pi extensions from loading and starting background services such as MCP. Standalone Pi remains unchanged; tests: `tests/chat.rs`, `tests/codex_auth.rs`, `tests/auth_handoff.rs`. Code boundaries: `src/main.rs` parses CLI arguments; `src/chat/` owns chat/model/session workflows, `src/pi/` owns transport/dialog protocols, and `src/tui/` owns terminal presentation. The folder map is documented in `docs/architecture.md`. A single long-lived RPC child handles multi-turn chat; `--continue` resumes the latest directory session and `new_session` starts another. `--sessions` lists Pi's existing per-directory JSONL session files, then opens the selected file via Pi `--session`; in-chat `/continue` and `/sessions` use Pi `switch_session` RPC (unless the target is already active). No parallel history store is needed. Mock integration tests: `tests/in_chat_sessions.rs`.

- **Terminal presentation:** Interactive chat uses an alternate-screen renderer (`src/tui/screen.rs`) with a fixed composer, reusable selection state (`src/tui/picker.rs`), and lightweight Markdown display transform (`src/tui/markdown.rs`); Pi remains the source of model/session status (`get_state`) and raw Markdown. Picker panels and slash suggestions are docked above the composer; the transcript is rendered into the remaining rows rather than painted underneath the panel. Apply the same outer left margin to panel rows as to transcript/composer rows or the popup shifts left in wide terminals (`tests/models_tty.rs`). Live slash suggestions come only from supported Hibiscus commands (`src/chat/commands.rs`) and do not query Pi on each keystroke. When a bare Esc is immediately followed by another key, preserve the consumed key (`Navigation::EscapeWith`) so dismissing suggestions or a picker does not eat the next command; tests: `escape_dismisses_suggestions_without_discarding_input` and `tests/models_tty.rs`. Keep piped output plain, and suspend/restore the alternate screen and mouse reporting across Pi auth handoffs and shutdown. Mouse-wheel CSI sequences must not be mistaken for Esc interruption; `active_keys` routes them to viewport scrolling. Clamp transcript scroll to `max(total rendered lines - visible rows, 0)`, not `total - 1`: the latter strands a few oldest lines above a mostly blank screen. Regression tests: `transcript_scroll_stops_at_a_full_page` and `tests/tty.rs`. `NO_COLOR` disables SGR color, while `TERM=dumb` and small terminals use line mode. Metadata labels are stripped of controls and long session filenames are not displayed. PTY tests must drain output concurrently to prevent the render stream from blocking on a full PTY buffer (`tests/tty.rs`). Full-screen PTY fixtures must set child `TERM=xterm-256color` and an explicit 80×24 window. A PTY alone does not enable full-screen mode: inherited `TERM=dumb` or absent `TERM` selects line mode, skipping the provider picker. This caused auth-handoff failures on both Linux and macOS CI; the earlier timing-only diagnosis was incorrect. Auth PTY suites use `tests/support/mod.rs` with nonblocking I/O, bounded output, deadline-driven prompt/exit waits, and isolated process-group cleanup on drop. Fixed sleeps in the Codex driver have been replaced by prompt/reply synchronization; the slow-SDK test injects a 1.5-second startup delay. Full-screen redraws re-emit old transcript text, so even a cursor into newly captured bytes can match a previous reply. Auth fixtures use turn-specific reply markers followed by the idle footer before sending the next command; a deliberate mock delay between text and `agent_settled` guards against treating visible text as completion. Otherwise `/quit` can be sent during an active run and discarded by active-key handling. CI runs tests with parent `TERM=dumb` to catch inheritance regressions.

## Confirmed pitfalls and fixes

- **WSL build prerequisite:** Rust/Cargo alone are insufficient on minimal Ubuntu/WSL installs: `cargo test` and `cargo install --path .` can fail with `linker cc not found` while compiling dependencies. Install `build-essential` (provides `cc` via GCC) before retrying. User subsequently reported builds working.
- **Session fixture path identity:** `temp_dir()` may include symlinks (macOS `/var` vs `/private/var`), while the subprocess's `current_dir()` returns the physical path. Canonicalize the created fixture root before generating session headers and mock paths; otherwise exact workspace filtering rejects every session. Reproduced on Linux with symlinked `TMPDIR`; regression: `sessions_work_when_fixture_parent_is_a_symlink` in `tests/in_chat_sessions.rs`. This fixes fixture consistency, not production path-matching semantics.
- **Resume display:** Pi's persisted history need not be copied to Hibiscus storage. Query `get_messages` after opening the target session, and render the last five user turns plus their visible assistant text. Exclude system, tool, and thinking content. Tests: `shows_only_last_five_user_turns_and_their_replies` and `chat_reuses_rpc_process_and_new_session`.
- **Model and auth boundaries:** In-chat `/models` uses Pi RPC `get_state`, `get_available_models`, and `set_model`, filtered to the current provider. Full-screen pickers for models and sessions use arrow/wheel/PageUp/PageDown navigation with a five-row sliding viewport; the model list marks the current ID and selecting it skips `set_model`. PTY test: `tests/models_tty.rs`. Pi RPC has no `/login` or `/logout` command: do not send them as prompts. Auth is independent of the selected model: after logout Pi can select another available model or none, so `/login` must ask for Codex vs another provider rather than gating Codex OAuth on `get_state.model.provider`. For full-screen Codex `/login`, `src/pi/auth.rs` runs an embedded Node helper using Pi SDK `ModelRuntime.login("openai-codex", "oauth", interaction)` so Pi handles OAuth/storage. The helper relays prompts/notifications over JSONL without returning credentials; manually entered redirect codes are masked and excluded from the transcript. Treat its `done` event (sent after SDK login/storage finishes) as authoritative, not natural process exit. A live freeze was traced to Rust waiting for the auth helper while it retained a browser connection on callback port 1455: Node's HTTP `server.close()` can stop listening without releasing preconnected sockets. After the protocol loop ends, terminate/reap the dedicated helper before returning the outcome; deliberate cleanup must not override a successful `done`. Regression: `completed_login_reconnects_without_waiting_for_browser_connection_to_close` in `tests/codex_auth.rs` holds a real local socket open after fake SDK completion. Browser OAuth URLs must not be printed as ordinary transcript lines: wrapping splits them and makes copying unreliable. `Screen` keeps the validated URL in transient memory, renders a short OSC 8 hyperlink, and offers explicit Ctrl+Y OSC 52 clipboard copy; the URL is cleared after the flow. Tests: `oauth_url_is_short_clickable_label_and_clipboard_encoding_is_complete` and `tests/codex_auth.rs`. On success `Rpc::reconnect` gracefully closes the idle child before reopening the saved session; an empty unsaved chat starts a new session. Tests: `tests/codex_auth.rs` uses a fake SDK (no real OAuth) and `tests/auth_handoff.rs` covers fallback. Other providers, `/logout`, or missing SDK/Node still hand the restored terminal to Pi's TUI: close the RPC child first (prevent concurrent session writers), stop/join the raw `/dev/tty` reader, open the saved session when present or `pi --no-session` for an empty chat, then reopen Hibiscus's RPC child. Tests: `tests/codex_auth.rs` logged-out provider choice, `tests/auth_handoff.rs` empty and saved handoff. Real provider auth refresh is unverified.
- **Stoppable terminal reader:** Use an independently opened `O_NONBLOCK` terminal reader with bounded `select` waits; `try_clone` shares file status flags and must not be used to set nonblocking mode on the output handle. The former reader ignored `poll.revents` and then used blocking reads, leaving shutdown vulnerable to error/stale readiness. Stop and join the reader before handing input to Pi. Regression: `idle_terminal_reader_stops_without_an_extra_keypress` in `src/tui/terminal.rs`, plus the handoff test's mock readiness marker before any extra input.
- **Extension UI and Esc:** RPC extension dialogs need matching `extension_ui_response` IDs. Only a real interactive terminal can approve; non-interactive runs cancel dialog requests (no automatic approval). Esc during a run sends `clear_queue` then `abort`, waits for their responses and `agent_settled`, and keeps the Pi process alive. Raw `/dev/tty` input and a separate Pi stdout reader let Esc work during active streaming. Tests: `tests/dialog_tty.rs`, `tests/tty.rs`, and `escape_sends_clear_then_abort_and_preserves_session`.
- **Live progress and tool lifecycle:** `src/pi/rpc.rs` starts and stops `Screen` activity with a prompt and ticks it while polling Pi, so the flower animates even when no events arrive. `thinking_start`/`thinking_delta` update phase without exposing raw reasoning; `tool_execution_start` and `tool_execution_end` correlate by `toolCallId` and show sanitized read/write/edit paths and Pi's `isError` outcome. Never show bash command arguments or raw thinking. The exception to hiding tool results is a bounded preview of Pi's authoritative `tool_execution_end.result.details.diff` for successful `edit` calls; do not synthesize it from requested edits or show it on failure. `src/tui/markdown.rs` treats these prefixed lines as literal diff content with added/removed/context theme colors and colors reasoning/tool notes; `NO_COLOR` remains plain. Tests: `tests/tty.rs`, `edit_preview_uses_result_details_and_limits_output`, `colors_activity_and_keeps_edit_diff_literal`, and `activity_and_diff_use_theme_colors_when_enabled`.
- **RPC prompt completion:** A `prompt` response confirms acceptance only. `agent_end` may be followed by retries or queued work. Wait for `agent_settled` before considering a run complete. The test `prompt_stream_waits_for_settled_and_supports_next_command` in `src/pi/rpc.rs` exercises this.
- **RPC stream separation:** Read stdout as LF-delimited JSON records, including while Pi is running; treat stderr as diagnostics only. Never parse stderr as protocol records. `src/pi/rpc.rs` uses a separate stderr reader; `strict_lf_framing_accepts_unicode_separators` tests LF framing.
