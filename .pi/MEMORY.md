# Durable project memory

Keep enduring decisions and evidenced pitfalls here. Current work, unresolved reports, hypotheses and test runs belong in `STATE.md`; release history belongs in Git and `CHANGELOG.md`. These records never replace reading the affected code.

## Evidence discipline

- **Implemented is not verified.** Code inspection proves an implementation exists. Unit/mock/PTY tests prove only their scenarios. A terminal screenshot or user confirmation applies only to the behavior/build observed, not every platform or a later revision.
- Record test commands, outcome, environment and snapshot in STATE. Do not accumulate a diary of passing test counts or copy feature descriptions into MEMORY. A source change makes earlier verification historical.
- Keep a user-reported bug open as “candidate fix, retest pending” until the relevant reproduction has been checked. A green suite does not override a later user report. Say exactly what was tested; avoid blanket “works,” “fixed,” “safe,” or “identical to Pi” claims.
- Separate facts from hypotheses. Promote a cause/fix to durable memory only with code evidence and a reproducer/regression where feasible. Merge by root cause rather than adding an entry for each recurrence.
- Preserve the agreed behavior when changing UI: show a draft/mockup when asked, make targeted changes, and test regressions in adjacent flows. Do not silently substitute hiding the cursor for making it steady.
- Never commit credentials, auth URLs/codes, private screenshots/transcripts, or user-specific machine configuration. Use synthetic fixtures. Do not mutate real provider credentials merely to run verification.

## Architectural boundaries

- **Pi owns the agent.** Hibiscus is a Rust client of a long-lived `pi --mode rpc` child, not a second agent, retry engine, credential manager, or session database. `src/chat/` owns workflows, `src/pi/` integration, and `src/tui/` presentation. Map: `docs/architecture.md`.
- **Protocol:** strict LF-delimited JSONL on RPC stdout; diagnostics stay on stderr. Correlate responses by ID. Prompt acceptance is not completion; `agent_end` can precede retries/recovery/queued work. Use `agent_settled` for run completion. Unknown event types are not inherently errors. Buffered command serialization must disarm `BufWriter` on failure: its Drop can otherwise retry an uncertain write. Regression: `buffered_command_does_not_retry_a_failed_write_on_drop`. Borrow image payloads during serialization and move response data instead of duplicating large JSON values. Evidence: `src/pi/rpc.rs` tests and `src/pi/run.rs`.
- **Transport overload:** do not put a blocking bounded channel behind a synchronous Pi stdin writer: a peer filling stdout before reading stdin can deadlock both pipes. `pi/transport.rs` uses raw-frame byte/count budgets and explicit connection invalidation on overload, plus nonblocking writes with deadlines and input servicing. This is fail-fast protection, not transparent flow control or a total RSS bound. Never append abort bytes to an incomplete JSONL record; disconnect with uncertain delivery and require explicit review. Validate slow consumers, duplex floods, modal approvals, cancellation and large-image sends (`transport` unit tests, `tests/rpc_pressure.rs`; limits in `docs/rpc-transport.md`).
- **Queues:** send explicit steering/follow-up behavior through Pi, not a separate local scheduling loop. A queue acknowledgement is not delivery. Pending UI and transcript insertion are distinct; user-message events are the delivery signal. Preserve newer typing on rejection and never automatically replay an uncertain request after disconnect. Failed queued writes and the newest unacknowledged submission on receive failure use the single explicit `/restore` slot; do not describe this as recovery of every accepted Pi queue entry. Ordering/identity limitations stay in STATE. Evidence: `tests/steering_tty.rs`.
- **Errors:** distinguish request failures from transport/protocol failures. Interactive request failures should retain chat; one-shot/piped failures keep nonzero exit status. Successful Pi retries must supersede earlier failed attempts, not inherit a sticky failure flag. Provider-string categories are advisory hints only; quota/billing can also be HTTP 429. Evidence: `src/pi/error.rs`, `src/pi/run.rs`, `tests/error_recovery.rs`; limits in `docs/error-handling.md`.
- **Sessions:** Pi is the persistence authority. Clear the local `/new` view only after successful creation; rejected/cancelled creation must retain it. Do not delete saved sessions to clear the screen. Resume renders recent visible user/assistant text, not system/tool/thinking content or image data. Session-title caching is bounded, process-local and disposable; validate file identity/size/mtime/ctime, expire periodically, and invalidate deletions/replacements/workspace changes. Do not stop scanning at the first prompt: later records can rename a session. Regression: `cache_reuses_unchanged_files_and_invalidates_rename_replace_delete_and_scope`. Evidence: `tests/chat.rs`, `tests/in_chat_sessions.rs`, `tests/new_session_tty.rs`.

## Tools, auth and sensitive data

- **Explicit integration only:** disable Pi extension discovery and explicitly load Hibiscus's bundled extension with a tools allowlist. A tools allowlist alone does not prevent installed extensions/MCP startup. The worktree includes `goal` alongside `read,bash,edit,write`; inspect `configure_builtin_tools` before changing flags. Do not alter standalone Pi's global settings to implement repository behavior.
- **Approvals:** enforcement belongs before execution in Pi's `tool_call` hook, not in the later `tool_execution_start` notification. Deny/Cancel must be defaults; absent UI, timeout or dialog failure must not authorize a flagged operation. Do not persist or widen an exact session-scoped approval implicitly. The regex gate is **not a sandbox** and cannot certify arbitrary shell behavior. Evidence: `src/pi/approval.mjs`, `tests/approval.mjs`, `tests/approval_tty.rs`.
- **Goal display:** percentage must come from an explicit checklist, not tool counts, elapsed time or an invented estimate. It is model-reported progress, not independent verification of work. Store/reconstruct checklist snapshots through Pi's session data. Evidence: `goal` in `approval.mjs`, `tests/approval.mjs`, `tests/goal_tty.rs`.
- **Auth boundary:** login/logout are not ordinary RPC prompts. Use the selected Pi installation's SDK for supported inline flows; Pi owns storage and refresh. An absent/different active model must not prevent choosing a stored provider. Logout removes stored credentials only, not environment/config credentials or provider-side access. Close the idle RPC writer before authorized logout mutation and reload it afterward, including uncertain post-mutation failures. Evidence: `src/pi/auth.rs`, `src/pi/logout.rs`/`src/pi/logout.mjs`, `tests/codex_auth.rs`, `tests/logout.rs`.
- **Helper completion pitfall:** OAuth helper `done` is authoritative. Waiting for natural process exit can hang on retained browser callback sockets. Terminate/reap the dedicated helper after the result; a deliberate cleanup kill must not overwrite reported success. Regression: `completed_login_reconnects_without_waiting_for_browser_connection_to_close`.
- **Terminal handoff:** stop/join the input reader and restore terminal state before handing ownership to Pi; avoid concurrent Pi session writers. Reconnect the saved session when known. Tests: `tests/auth_handoff.rs`. Failed/unknown request outcomes must not be silently replayed.
- **Clipboard:** WSL's Pi default is Alt+V; other platforms use Ctrl+V. Terminal interception can prevent Ctrl+V reaching Hibiscus. Clipboard reads are explicit, bounded and cancellable; send image content through Pi RPC, never base64 in visible chat. Tests: `tests/image_paste.rs`, clipboard module tests. Clipboard-using fixtures must shadow every platform reader (`osascript`, `powershell.exe`, `wl-paste`, `xclip`) and assert which mock ran. Setting `WAYLAND_DISPLAY` does not select Wayland on macOS: the macOS branch chooses `osascript` first. A Wayland-only mock lets macOS tests access the runner's real clipboard, producing attachment timeouts unrelated to the behavior under test. Regression: `clipboard_fixture_covers_all_platform_readers` and platform-reader log assertions in `tests/steering_tty.rs`. Do not interpret mocked helper success as real desktop support.

## UI and testing contracts

- **User preferences:** visible steady composer cursor, movable editing, aubergine background, flower/Explore activity indicators separate from the cursor, and live status left/explicit Goal right on one footer row. During streaming, distinguish waiting input from delivered chat. These are requirements, not claims of flawless rendering.
- **Rendering:** preserve `NO_COLOR`, plain piped output and terminal restoration. Cached row-diff output must invalidate on resize/resume or untracked terminal writes. Synchronized output needs balanced release on error/exit; keep a fallback for incompatible terminals. Cache transcript layout independently of row-diff painting; output-frame counts alone do not bound parser work or input latency. Cache at explicit role-reset boundaries (not arbitrary lines) to preserve fences/table lookahead, invalidate on content/timeline/width changes, and apply coalesced scroll row deltas once at layout time. Printable input batches must stop before controls and preserve partial UTF-8. A PTY byte assertion cannot prove absence of visual flicker. Evidence: Markdown/layout/batching unit tests, `tests/performance_tty.rs`, `src/tui/paint.rs`, `tests/rendering_tty.rs`, `tests/working_cursor_tty.rs`.
- **Dialogs:** full-screen prompts must use the shared modal component, not raw writes over the composer. Preserve drafts, response IDs and safe defaults; display long command details without silent omission. Current bottom-page review tracking is not proof of complete human review. Evidence: `src/tui/modal.rs`, `tests/modal_tty.rs`.
- **Tool display:** use Pi tool-call IDs for lifecycle correlation and Pi `result.details.diff` for successful edit previews. Never invent a diff from requested edits or show a failed edit as successful. Do not expose raw reasoning or routine bash arguments. Approval review necessarily displays the command being authorized. Tests: `tests/tty.rs`, `tests/goal_tty.rs`.
- **Terminal-reader pitfall:** use a separate nonblocking open for the stoppable `/dev/tty` reader. `try_clone` shares file-status flags; changing nonblocking mode can affect the output handle. Bound waits, stop and join before handoff. Regression: `idle_terminal_reader_stops_without_an_extra_keypress`.
- **PTY fixtures:** explicitly set TERM and window dimensions, drain output concurrently, and bound waits/cleanup. A PTY alone does not ensure full-screen mode. Prefer `tests/support/` to sleep-based drivers. Row-diff output requires a reconstructed view; previously displayed text is not proof of a new response or settlement. Use distinct response markers and the correct idle/event boundary.
- **Fixture paths:** canonicalize temp roots (macOS `/var` and `/private/var` can differ). Use atomic IDs plus exclusive directory creation, not clock+PID alone, for parallel fixtures. Regressions: `tests/pty_harness.rs`, `tests/in_chat_sessions.rs`.
- **Build prerequisite:** minimal Ubuntu/WSL needs a C linker (`build-essential`), not only Cargo. Record a tooling blocker rather than claiming tests passed.

Contribution PRs should branch from upstream `dev` and target `dev`, not `main`; see `CONTRIBUTING.md` and the CI trigger in `.github/workflows/ci.yml`.
- Prebuilt archives target Linux musl and macOS, x86-64/ARM64, with checksums; macOS binaries are ad-hoc signed, not notarized. The updater uses the embedded pinned installer, stages/replaces atomically, and refuses unsupported locations/symlinks. Source/Cargo installs are updated separately. Details: `docs/installation.md`, `tests/install.sh`, `tests/update.rs`.
- Use `scripts/bump-version.sh`; review Cargo manifest/lock, installation docs, installer fixture **and changelog**. Verify version at the exact tagged commit; never silently move a public tag. A dev push is not a release or proof remote CI passed. Artifact-only publishing requires `GH_REPO` because there is no checkout. Check current workflow files before release work.
- README artwork is an explicitly labeled illustration, not a captured run. The release-download badge counts assets (including checksums/repeats), not unique users or Cargo/source installs. Guidance: `docs/assets/README.md`.
